# Model Card

## Model scope

This repository supports two image-classification models for the Kaggle flower dataset:

- `custom_cnn`: the modernized version of the original hand-built CNN baseline
- `resnet18`: a transfer-learning baseline using `torchvision` ResNet18

## Dataset

- Source: [Kaggle Flowers Recognition](https://www.kaggle.com/alxmamaev/flowers-recognition)
- Classes: daisy, dandelion, rose, sunflower, tulip
- Expected raw layout: `data/raw/flowers/<class-name>/*.jpg|png`
- Split policy: deterministic train/validation/test split generated by
  `flower-prepare-data` and recorded in `data/processed/split-manifest.json`

## Training metadata

Each checkpoint stores:

- Resolved config values
- Class-name ordering
- Preprocessing metadata
- Dataset fingerprint
- Optimizer state
- Scheduler state
- Training history

## Evaluation outputs

Each run writes a held-out evaluation bundle with:

- `summary.json`
- `predictions.csv`
- `sample_errors.json`
- `confusion_matrix.png`

These files are the source of truth for measured results.

## Intended use

- Educational and portfolio demonstration
- Local experimentation with reproducible ML workflows
- Comparing a custom CNN against a transfer-learning baseline on the same split

## Limitations

- Metrics depend on the user supplying the Kaggle dataset locally.
- No public pretrained weights are committed in this repository.
- The custom CNN is included as a baseline, not as a claim of state-of-the-art performance.
- Results should be reported from generated evaluation artifacts, not from memory or console output.

## Safety and misuse considerations

- Do not load untrusted checkpoints outside your own controlled environment.
- Treat predictions as a lightweight demo, not as a scientifically validated plant-identification tool.

## Reproducibility checklist

- Lock environment with `uv.lock`
- Keep the generated split manifest
- Save run artifacts under `artifacts/runs/<run-id>/`
- Report metrics from `evaluation/test/summary.json`
